# Baseline A

Калибровочный реальный эксперимент для первого раунда `PLAN-LATENCY-001`.

```text
target:   GET http://127.0.0.1:9000/
warm-up:  10 req/s, 10 s (сохранён отдельно во временном файле)
measure:  10 req/s, 60 s
timeout:  2 s
client:   Vegeta 12.13.0
result:   600 ответов HTTP 200
```

`baseline-a.gob` — исходный результат Vegeta без преобразования.

`baseline-a.csv` — полное CSV-представление того же результата через `vegeta encode`.

## Промежуточный вывод

Данные получить удалось. Готового универсального пути от нового источника к старым статистическим функциям — нет.

Существующие функции делались под старый кортеж `(status, latency)` и смешали формат источника со статистическим контрактом. Более того, функция с названием `calculate_empirical_moments` считает моменты Bernoulli-переменной статуса, а не latency.

На текущем шаге это не ремонтируется. Для возврата к исследованию используется прямой разбор третьей колонки Vegeta, перевод наносекунд в миллисекунды и расчёт `mean`, `variance`, `std` с `ddof=0`.

Получено:

```text
mean     = 0.7333737967 ms
variance = 0.2483922664 ms^2
std      = 0.4983896732 ms
```

Среднее согласуется с отчётом самой Vegeta.
