# Issue #5: Real Server Latency: From Empirical Baseline to Parametric Model

- **State:** Open
- **Created:** 2026-08-31
- **Updated:** 2026-09-02
- **Source:** https://github.com/kshakirov/Agnostic-Inference-Engine/issues/5

## Зачем

Перестать крутить только синтетику и пройти всю машину вывода на живом сервере:

```text
сырой ответ сервера
-> эмпирика
-> гипотеза о распределении
-> MLE
-> оценка неопределённости
-> проверка модели на новых данных
```

Объект, данные, модель и оценки параметров не смешиваются. Normal — кандидат, а не заранее назначенная истина.

## Первый стенд

- локальный Haskell proxy;
- `GET http://127.0.0.1:9000/`;
- нагрузка через Vegeta;
- timestamp, HTTP status и latency сохраняются для каждого запроса;
- нагрузка сервера управляется частотой запросов и объёмом печати в консоль.

## Что должно получиться

- воспроизводимый протокол измерения;
- сохранённые сырые данные;
- эмпирические характеристики latency;
- явная параметрическая гипотеза;
- оценки параметров и их неопределённости;
- условия, при которых модель проигрывает;
- проверка на новой серии данных.

## Связь

Issue #4 остаётся синтетическим стендом и Ground Truth для MLE. Этот тикет — применение той же машины к объекту, настоящие параметры которого неизвестны.

## Comment: ECDF оставлена домашкой

Источник: https://github.com/kshakirov/Agnostic-Inference-Engine/issues/5#issuecomment-5489022641

Сегодня сначала разобрался, что именно уже есть на руках.

Для 600 latency посчитаны:

```text
mean     = 0.7333737967 ms
variance = 0.2483922664 ms^2
std      = 0.4983896732 ms
```

Это пока просто эмпирика конкретной выборки. `mean +- std` само по себе не даёт интервал с какой-то известной большой вероятностью и ещё не предсказывает следующий запрос. Для предсказания надо добавить предположение, что режим сохраняется, и модель формы распределения.

Дальше прояснились две дороги:

```text
эмпирическое распределение -> функционалы -> bootstrap их разброса

или

гипотеза Normal -> MLE -> Фишер -> проверка модели
```

Отдельно встал на место старый вопрос про MLE. Для Normal он действительно даёт те же выборочные среднее и дисперсию. Новые числа из воздуха не появляются. Меняется статус этих чисел: из простых функционалов выборки они становятся оценками параметров принятой Normal-модели, после чего появляется likelihood, Фишер и аппарат неопределённости.

Чтобы не назначать Normal заранее, пошёл к форме данных через ECDF. Понял конструкцию:

```text
x = latency, отсортированные по возрастанию
y = накопленная доля: 1/n, 2/n, ..., n/n
```

С первой реализацией перемудрил: поделил прямой индекс на обратный и затем умножил результат на latency. Это неправильно. Значение ECDF не вычисляется из величины latency: latency задаёт место скачка по x, а нормированный ранг задаёт высоту по y. В текущем коде ещё есть деление на ноль в конце обратного массива.

Специально оставил коммит `f8fe974` как незаконченный ход, а не стал приглаживать историю.

Домашка на следующий раз: спокойно выразить через NumPy два массива `(x, y)` без Python-цикла, проверить механику на маленькой ручной выборке и только затем применить её к 600 latency и построить ECDF.

## Comment: эмпирика добита, план проверки Normal

Источник: https://github.com/kshakirov/Agnostic-Inference-Engine/issues/5#issuecomment-5504236387

Эмпирику таки добил.

Для ECDF теперь получаются два массива без Python-цикла:

```text
x = отсортированные latency
y = накопленные доли 1/n, 2/n, ..., n/n
```

Сначала перемудрил с обратным индексом и умножением на latency, потом дошло: latency задаёт координату скачка, а нормированный ранг — его высоту. Сейчас механика правильная, но перед применением ко всему стенду ещё проверю её на маленькой ручной выборке.

Среднее и дисперсия сами по себе форму распределения не определяют. Поэтому дальше Normal проверяется не повторным сравнением `mean/std`, а прямым сравнением всей эмпирической CDF с CDF нормальной модели.

Рабочий план:

1. Проверить ECDF на маленькой выборке: `x` отсортирован, `y` идёт от `1/n` до `1`.
2. Для 600 latency построить Normal-CDF с уже найденными `mu_hat=0.7333737967 ms` и `sigma_hat=0.4983896732 ms`.
3. Получить максимальное вертикальное расхождение `D_real` между ступенчатой ECDF и Normal-CDF. Проверять обе стороны каждого скачка.
4. Сделать параметрический bootstrap: много раз сгенерить по 600 значений из fitted Normal, для каждой реплики заново оценить `mu_hat*`, `sigma_hat*`, построить её ECDF и её fitted Normal-CDF, сохранить `D*`.
5. Посмотреть, какая доля `D* >= D_real`. Если реальное расхождение обычно для нормальных выборок такого размера, Normal пока не проиграла. Если `D_real` далеко в хвосте — модель подозрительна.
6. После проверки формы сравнить неопределённость параметров тремя способами: Фишер, параметрический bootstrap и эмпирический bootstrap.

Полный план лежит в Wiki `PLAN-LATENCY-001 — От сервера к модели`. Выполняю по одному пункту, чтобы опять не потерять смысл за инструкциями.

## Comment: остановка на двух сторонах скачка ECDF

Источник: https://github.com/kshakirov/Agnostic-Inference-Engine/issues/5#issuecomment-5504791459

Сегодня дошёл от ECDF до первого прямого сравнения с Normal-моделью.

Что сделал:

1. Упорядочил ad hoc-скрипт: отдельно подготовка latency из Vegeta CSV, отдельно ECDF.
2. ECDF возвращает два массива:

```text
x = отсортированные latency
y = 1/n, 2/n, ..., n/n
```

3. Для Normal-CDF использовал не самописный численный интегратор, а `erf` из стандартной библиотеки:

```text
z = (x - mu_hat) / sigma_hat
F(x) = 0.5 * (1 + erf(z / sqrt(2)))
```

4. Зафиксировал `mu_hat` и `sigma_hat` частичным применением, затем через `np.vectorize` получил Normal-CDF во всех 600 реальных точках.
5. Сравнил Normal-CDF с верхней стороной ступеней ECDF и получил:

```text
D_after = 0.33018544917945775
```

Это максимальное вертикальное расхождение примерно в 33 процентных пункта. Сигнал сильный, но приговор Normal пока не выносится: ещё нет полного `D_real` и bootstrap-распределения `D*`.

Остановился на важной тонкости. В точке `x_i` ECDF скачет:

```text
(i - 1) / n -> i / n
```

Текущий расчёт видит только расстояние после скачка. Для стандартной статистики Колмогорова—Смирнова надо проверить Normal-CDF с обеих сторон ступеньки. Я понял формальную механику, но хочу ещё спокойно продумать её смысл, а не просто исполнить формулу.

Следующий ход:

1. построить нижние значения ступеней `0/n, 1/n, ..., (n-1)/n`;
2. получить второе максимальное расстояние;
3. взять максимум двух сторон как полный `D_real`;
4. только после понимания этого шага переходить к параметрическому bootstrap.

## Comment: Normal не выдержала первую проверку

Источник: https://github.com/kshakirov/Agnostic-Inference-Engine/issues/5#issuecomment-5520544269

Сегодня добил пункты 3 и 4 плана.

Посчитал полный разрыв между реальной ECDF и fitted Normal-CDF по обеим сторонам скачка:

```text
D_before = 0.33185211584612445
D_after  = 0.33018544917945775
D_real   = 0.33185211584612445
```

Затем сделал параметрический bootstrap. Для каждой из 1000 Normal-реплик заново оценил её собственные `mu` и `sigma`, построил ECDF и посчитал такой же `D*`. В контрольном прогоне максимальный `D*` оказался около `0.05`, то есть реальный разрыв `0.332` лежит далеко за всем увиденным bootstrap-диапазоном.

Нарисовал histogram реальных latency вместе с fitted Normal PDF. График показал причину без magic: основная масса данных прижата слева, есть длинный правый хвост, а Normal симметрична и ещё отдаёт вероятность отрицательной latency. Значит, одной пары `mean/std` оказалось недостаточно: Normal с этими MLE-параметрами форму данных не описывает.

Вывод: гипотеза Normal первую проверку не выдержала. На Poisson форма похожа лишь внешне, но latency непрерывна, а Poisson — модель числа событий.

Следующий пункт: явно посчитать долю bootstrap-реплик с `D* >= D_real`, зафиксировать результат проверки и только потом исследовать хвост и выдвигать следующего кандидата — Gamma, Lognormal, Weibull либо непараметрическую модель.

## Comment: KS откалиброван, Normal проиграла

Источник: https://github.com/kshakirov/Agnostic-Inference-Engine/issues/5#issuecomment-5595802879

Проверку Normal закончил и отдельно разобрал, что именно здесь измерялось.

```text
D_real = 0.331852
count(D* >= D_real) = 0 / 1000
p_hat = (0 + 1) / (1000 + 1) ≈ 0.001
```

`D*` не сравнивает искусственные выборки с реальной ECDF. Оно калибрует обычное расхождение ECDF со своей fitted Normal в мирах, где Normal заведомо верна. После этого `D_real` кладётся на полученную шкалу.

Максимальный провал найден при `latency = 0.52579 ms`: реальная ECDF до скачка накопила около `0.67%`, а Normal-CDF — около `33.85%`. Правый хвост раздул `sigma`, а симметричная Normal выдумала почти отсутствующий в данных левый хвост.

Вывод: Normal проиграла не только визуально. KS измерил расхождение, bootstrap дал шкалу случайной погрешности, `p-value` оформил решение.

Полный разбор вынесен в Wiki `STAT-GOF-001 — Как Normal проиграла проверку`. Это дополнительная ветка проверки самой модели, а не неявное продолжение текущего маршрута главы 9 Вассермана.

Следующий ход: исследовать правый хвост и только потом выставлять следующую модельную версию.
